# 当日ネットワーク手順書（家のルータで隔離LANを作る）

4人・1部屋の演習用。**インターネットは不要**。必要なのは「5台（Mac＋参加者4人）が互いに
通信できる閉じたLAN」だけ。大学Wi-Fiは端末同士の通信を遮断（AP隔離）しているので使えない。

## 方針

- **家のWi-Fiルータを持参**し、会場で**電源だけ**入れる（WAN=外線は挿さない）。
- Mac をその Wi-Fi につなぎ、Mac 上で CTFd と制御装置サーバを動かす。
- 参加者4人も同じ Wi-Fi につなぎ、ブラウザと `mbclient.py` で Mac に接続する。
- これで会場網・インターネットから完全に分離された演習用LANになる。

```
            家のルータ（WAN未接続・電源のみ）
                  │ Wi-Fi（SSID/パスワードは把握しておく）
   ┌──────────────┼───────────────┐
  Mac            参加者PC ×4
  ・CTFd  http://<MacのIP>:8000
  ・制御装置  <MacのIP>:5020
```

## 事前に用意するもの

- 家の Wi-Fi ルータ本体 ＋ **電源アダプタ**（忘れやすい）
- そのルータの **SSID と パスワード**（参加者に共有する）
- Mac（CTFd・制御装置サーバを動かす）

## 明日の実験（本番前に必ず1回）

### 実験A: 家ルータが「WANなし」でLANとして使えるか（自宅で）
ごく稀に、外線が無いと DHCP を止める機種がある。これだけは事前確認が必須。

1. ルータの **WAN（外線）ケーブルを抜く**（会場と同じ「インターネット無し」を再現）。
2. Mac と スマホ（または別PC）を、そのルータの Wi-Fi につなぐ。
3. Mac の IP を調べる: `ipconfig getifaddr en0`（Wi-Fi接続時）。出なければ `en1` も試す。
4. スマホ/別PC から Mac に届くか:
   - ブラウザで `http://<MacのIP>:8000` を開く → CTFd が見えれば成功。
   - （PCがあれば）`ping <MacのIP>` が返れば、端末同士の通信OK＝AP隔離なし。
5. これが通れば、当日も同じ構成で使える。

### 実験B: 自分で一周（本番の予行）
制御装置サーバと CTFd を起動し、参加者と同じ手順で全問解く。

```bash
cd /Users/shunikeda/gitClones/ot-demo-3d
python3 ctf/target.py --host 0.0.0.0 --port 5020      # 制御装置サーバ
# 別ターミナル
cd ctf/ctfd && docker compose up -d                   # CTFd（http://localhost:8000）
# まだ登録していなければ: python3 import_challenges.py
```
ブラウザで CTFd に自分のアカウントを登録し、`ctf/toolkit/mbclient.py` で段位1〜6＋ボーナスを解く。
難易度やヒントの出し方で気になる点をメモする。

## 当日の立ち上げ手順（会場で）

1. ルータの電源を入れる（WANは挿さない）。Mac をその Wi-Fi に接続。
2. Mac の IP を確認: `ipconfig getifaddr en0`（この値を参加者に伝える）。
3. **macOS ファイアウォール**: オンだと参加者から Mac に届かないことがある。
   - システム設定 > ネットワーク > ファイアウォール で、`python3` と `Docker` の受信を許可する。
   - 隔離ネットなので、演習中だけ**ファイアウォールを一時オフ**でも可（終わったら戻す）。
4. 制御装置サーバを起動: `python3 ctf/target.py --host 0.0.0.0 --port 5020`。
5. CTFd を起動: `cd ctf/ctfd && docker compose up -d`（登録済みなら問題はそのまま残っている）。
6. 自分のPCで疎通確認: `http://localhost:8000`（CTFd）、`python3 ctf/toolkit/mbclient.py --host 127.0.0.1 read-hr 0 5`（制御装置）。
7. 参加者に配るもの:
   - 接続先: CTFd=`http://<MacのIP>:8000`、制御装置=`<MacのIP>:5020`
   - 配布キット `ctf/toolkit/`（`mbclient.py` と README）。※制御装置の設計図・ソースは渡さない。
8. 参加者側の疎通確認:
   ```
   curl http://<MacのIP>:8000
   python3 mbclient.py --host <MacのIP> read-hr 0 5
   ```

## うまくいかないとき

| 症状 | 対処 |
|------|------|
| 参加者から CTFd が開けない | macOS ファイアウォールを確認（Docker/python3 を許可 or 一時オフ） |
| `mbclient` が制御装置に届かない | 制御装置サーバを `--host 0.0.0.0` で起動しているか。IP が正しいか |
| IP が取れない・Wi-Fi 不安定 | ルータの WAN を抜いても DHCP が動くか（実験A）。ダメなら予備手段＝スマホのテザリング（同時5台・端末隔離に注意） |
| 参加者同士/Macに ping が通らない | そのネットワークが AP 隔離をしている。大学Wi-Fiでは起きる。家ルータなら通常は通る |

## 予備手段（家ルータが使えない場合）

スマホのテザリングに全員つなぐ。ただし **iPhone は同時5台まで**が多く、Mac＋4人でちょうど限界。
機種によっては端末同士の通信を遮断することがあるので、使う前に実験A相当の疎通確認をする。
