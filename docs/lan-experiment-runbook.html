LAN実験 手順書（OT-CTF 第1回WS）

オフライン閲覧用 / 作成 2026-11-11 ・ このページはネット遮断後も開けます（ローカルHTML）
結論（この実験の目的）: 家のルータをWAN（外線）抜きで動かし、 Mac＋別端末が同じWi-Fiで通信できるかを本番前に1回確認する。 これが通れば当日も同じ構成で動く。確認するのは ① DHCPでIPが取れる ② 端末→Macに届く（AP隔離なし） の2点だけ。
前提メモ（今の環境）: 自宅での現在のMac IP = 192.168.11.15（参考値。 会場や別ルータでは変わるので、都度 ipconfig getifaddr en0 で取り直す）。 Python = /Users/shunikeda/gitClones/ot-lab/.venv/bin/python。 プロジェクト = /Users/shunikeda/gitClones/ot-lab/ws1-ctf。

Phase 0 ── 既存プロセスを止める（最初に1回）

今 Claude Code が 127.0.0.1（ローカル限定）で制御装置とウォールを動かしています。 LAN公開に切り替えるため、まず全部止めます。自分のターミナルで:

pkill -f run_arena.py ; pkill -f ctf/target.py ; pkill -f wall/wall.py
# 確認（何も出なければ停止済み）
lsof -nP -iTCP:5020 -sTCP:LISTEN ; lsof -nP -iTCP:8090 -sTCP:LISTEN

CTFd（Docker, ポート8000）は止めなくてOK。問題・スコアはそのまま残ります。

Phase 1 ── 実験A：WAN抜きでLANが機能するか

ごく稀に外線が無いとDHCPを止める機種があるため、ここだけは事前確認必須。

  1. ルータの WAN（外線）ケーブルを抜く（＝会場と同じ「ネット無し」を再現）。
  2. Mac と スマホ（または別PC）を、そのルータのWi-Fiに接続。
  3. MacのIPを調べる：
    ipconfig getifaddr en0   # 出なければ en1 も試す
  4. 別端末から届くか確認：
    • ブラウザで http://<MacのIP>:8000 → CTFdが見えれば成功。
    • 別PCがあれば ping <MacのIP> が返ればAP隔離なし＝OK。
  5. 通れば当日も同じ構成で使える。NGなら→ 下の「うまくいかないとき」へ。

Phase 2 ── 中央機（Mac）を LAN公開で起動

ポイントは --host 0.0.0.0（LAN全体から受付）。ターミナルを2枚使います。

ターミナル① 制御装置サーバ（4環境）

cd /Users/shunikeda/gitClones/ot-lab/ws1-ctf
/Users/shunikeda/gitClones/ot-lab/.venv/bin/python \
  ctf/run_arena.py --count 4 --base-port 5020 --host 0.0.0.0

起動すると「割り当て表」が出ます。そこに表示される <IP>:5020〜5023 が参加者の接続先。

ターミナル② 水槽ウォール（大画面用ダッシュボード）

cd /Users/shunikeda/gitClones/ot-lab/ws1-ctf
/Users/shunikeda/gitClones/ot-lab/.venv/bin/python \
  wall/wall.py --count 4 --base-port 5020 --target 127.0.0.1 --serve-port 8090

ウォールは http://<MacのIP>:8090（Macでは http://localhost:8090）を全画面表示。 Mac自身が制御装置に繋ぐので --target 127.0.0.1 のままでOK。

CTFd（すでに起動中。止めた場合のみ）

cd /Users/shunikeda/gitClones/ot-lab/ws1-ctf/ctf/ctfd && docker compose up -d
# 参加者は http://<MacのIP>:8000

Phase 3 ── 疎通確認

Mac自身から（まず自分で確認）

# 制御装置（水位レジスタを読む）
/Users/shunikeda/gitClones/ot-lab/.venv/bin/python \
  ctf/toolkit/mbclient.py --host 127.0.0.1 --port 5020 read-hr 10 1
# CTFd / ウォール
open http://localhost:8000
open http://localhost:8090

参加者端末から（別のスマホ/PCで）

curl http://<MacのIP>:8000                     # CTFdが返るか
python3 mbclient.py --host <MacのIP> --port 5020 read-hr 10 1   # 制御装置に届くか

参加者には 接続先（CTFd=:8000／制御装置=:5020〜5023） と 配布キット ctf/toolkit/（mbclient.py と README） だけ渡す。 制御装置のソース・設計図は渡さない。

うまくいかないとき

症状対処
参加者から CTFd/制御装置に届かない macOSファイアウォールが原因のことが多い。システム設定 > ネットワーク > ファイアウォール で python3 と Docker の受信を許可。隔離網なので演習中だけ一時オフでも可（終了後に戻す）。
mbclient が制御装置に届かない サーバを --host 0.0.0.0 で起動しているか。IPが正しいか（ipconfig getifaddr en0 で再確認）。
IPが取れない / Wi-Fi不安定 WANを抜くとDHCPが止まる機種かも（実験A）。予備＝スマホのテザリング（iPhoneは同時5台まで＝Mac＋4人が限界）。
ping/通信が通らない そのネットワークがAP隔離をしている。大学Wi-Fiで発生。家ルータなら通常は通る。

終了手順
