# AI利用時の解きやすさ検証（2026-11-10）

**問い**: 参加者がAIを使うと、本編CTF（偵察→…→溢水）はどれくらい速く解けてしまうか。
AI禁止にすべきか判断するための実測。

## 方法

的のソース・メモリマップを**一切参照しない**ブラックボックス解答器を、配布用クライアント
`ctf/toolkit/mbclient.py` だけで実装し、稼働中の的に対して実行。発見に要したリクエスト数と
経過時間を計測。解答器は `ctf/_facilitator/`（**参加者には配らない**）。

- 素朴版: 「定数っぽいレジスタを全部 0xFFFF、ONコイルを全部OFF」＝意味を考えない総当り。
- 推論版: 値の大きさで「しきい値(>100: 800/950/200) と レート(≤100: 15/8)」を分け、
  **排水を触らず**停止しきい値だけ潰し、安全コイルを落とし、ポンプを強制ON（＝LLMがやる推論）。

## 結果

| 版 | 発見 | 溢水 | 合計 | 備考 |
|----|------|------|------|------|
| 素朴（総当り） | 8req / 0.9s | **失敗** | — | 排水レートも0xFFFFにして自滅、水位が下がる |
| 推論（AI相当） | 8req / 0.9s | **成功** | **12.3s** | setpoint/safety/overflow の3フラグ取得。残り時間は水の物理待ち |

推論版の発見ログ:
```
水位=reg10  しきい値=[(11,800),(12,200),(13,950)]  レート=[(14,15),(15,8)]  ONコイル=[5,6]
→ しきい値0xFFFF / 安全OFF / ポンプON（レートは温存）→ 水位100.0% 溢水
→ FLAG{setpoint_tamper_no_stop} FLAG{safety_interlock_bypassed} FLAG{OVERFLOW__...}
```

## 分かったこと

1. **メモリマップの秘匿は、AIにはほぼ無効**。レジスタの値（800→80%、950→95%、15/8＝レート）は
   LLMには意味が自明で、分類→攻撃まで一瞬。発見は0.9秒。
2. **残り時間はほぼ"水が溜まる物理待ち"**。つまりAIありだと本編は実質"待つだけ"になり、
   60分どころか数分で終わる＝**人間が process を考える学びが丸ごと飛ぶ**。
3. 逆に**意味を理解しない総当りは自滅する**（排水を最大化してしまう）。AIなしの初学者には
   「給水/排水/しきい値の区別」「安全が2段」という**本物の思考の壁**が残る＝教育的。

## 推奨

本WSの価値は「人間がプロセスを読み解く」こと。AIはそれを丸ごと短絡する。4人・60分・公演形式なら:

- **第一推奨: 本編の推論パートはAI禁止**（Wireshark/Modbus一般の調べ物に限りAI可、等の線引き）。
  司会がヒントで速度調整する前提と相性が良い。
- AIを許すなら、**値を非意味化**する改修が要る（例: 水位スケールを変える・設定値を非自明な生値にする・
  給水/排水を似た値にして"書いて観察"しないと区別できなくする・MITMなど一手で終わらない段を足す）。
  手間が増えるので、今回は上の「AI禁止」が現実的。

## 再現

```bash
python3 ctf/target.py --host 127.0.0.1 --port 5097 --interval 0.1 &
python3 ctf/_facilitator/solver.py 5097     # 推論版
```
