# ot-demo-3d — Windows だけで回す OTセキュリティ謎解きWS

OTセキュリティ研究会 第1回ワークショップの**代替案**。物理ポンプ・タンク・PLC実機が
手に入らなかったため、**Modbus/TCP の構造的欠陥を体で学ぶ CTF 型ハンズオン**に置き換えたもの。
実機は使わず、**参加者のPC＋CTFd＋ソフトの的**だけで成立する（JRUは任意・次回送り）。

## ねらい

「**認証なし・暗号化なし・完全性チェックなし**」という Modbus の3欠陥が、情報セキュリティの
3要素（機密C/完全性I/可用性A）の破壊にそのまま対応する、という筋で**攻撃を自分の手で**体験する。
ゴールは「タンクを実際に溢れさせる（＝実害を出す）」。

## 構成

| ディレクトリ | 中身 |
|------|------|
| `ctf/target.py` | 攻撃対象の制御装置サーバ（Modbus/TCP。設計図を伏せ、ダミーのレジスタも混ぜる。攻撃成功でフラグがレジスタに出る） |
| `ctf/selftest.py` | 制御装置サーバの自己テスト（攻撃→フラグ読み出し→溢水まで検証） |
| `ctf/ctfd/` | CTFd（docker compose）＋ 問題一覧 ＋ 運用手順 |
| `ctf/takehome/` | 持ち帰り課題（制御プロジェクトを壊すとフラグが出る・JRU不要・自己完結） |
| `demo/index.html` | 溢水を見せる3Dビジュアル（Three.js・1ファイル。本物の通信値での駆動は今後） |
| `docs/design.md` | 全体設計メモ（当日の体験・攻撃シナリオ・将来のJRU連携） |

## クイックスタート（司会/準備）

```bash
# 1) 制御装置サーバを起動（中央ホスト=Mac）
python3 ctf/target.py --host 0.0.0.0 --port 5020
# 2) 動作確認
python3 ctf/selftest.py          # => 自己テスト PASS
# 3) CTFd 起動
cd ctf/ctfd && docker compose up -d   # => http://localhost:8000
```

詳細は `ctf/ctfd/README.md`（運用）と `ctf/ctfd/challenges.md`（問題・時間割）を参照。

## 注意（必読）

- **隔離ネット専用**。学内・会場網には接続しない。攻撃スクリプトはこの閉じた環境のみで実行する。
- 擬似ランサム等は対象を限定した**無害・可逆**なデモ資材のみ。本物のマルウェアは扱わない。
- 教育目的（OTセキュリティの防御理解）。多層防御（認証・分離・独立安全装置・復旧）を学ぶ構成。
