# OT-CTF チャレンジ一覧（CTFd 手入力用 / 司会プレイブック）

4人・協力・競争なしの「謎解き公演」。全員で1つの制御装置（タンク）を攻略する。**本編はAI禁止**なので、
**ヒントを手厚く**用意した（各段 H1 やさしい → H4 ほぼ答え）。司会は下の「ヒント解放スケジュール」で
速度を調整する。`<HOST>` は Mac(アリーナ) の隔離LAN上のIP。制御装置は `<HOST>:5020`、Modbus/TCP。

> フラグの考え方: 段位3以降は「攻撃に成功すると制御装置がフラグをレジスタに書き込む」。
> 参加者はそれを **Modbus で読み出して** 提出する（攻撃しないと値が出ない＝やった証明）。
> 段位1・2は「読み取った値そのもの」をフラグにする（値フラグ）。

---

## 0. 接続確認（配点0・最初から公開）
**説明**: 制御装置は `<HOST>:5020` で Modbus/TCP を話す。配布キットの `mbclient.py` で接続してみよう。
`python3 mbclient.py --host <HOST> read-hr 0 30` が通れば準備OK。
**フラグ**: なし（接続できたら自己申告）。CTFd を使わず口頭でもよい。
**ヒント**: ポートは標準の 502 ではなく 5020。

---

## 1. 偵察 — プロセスを読む（機密性C）
**説明**: 制御装置には複数の保持レジスタがある。**時間とともに変化する1本が水位**。
どの番号が水位かを観測で突き止め、その **レジスタ番号** を答えよ（例: 3番 → `FLAG{3}`、これは例）。
**フラグ**: `FLAG{10}`（＝水位レジスタの番号。画面には出ないし、例も答えではない）
**ヒント**:
- H1: `read-hr 0 30` を**何度も実行**して、**値が動くもの**を探せ。
- H2: 動く値は複数ある（**おとり**が混じる）。その中で **0〜1000 の範囲で小刻みに増減** する1本が水位。
  おとりは大きく乱高下するので見分けられる。
- H3: 見つけた水位レジスタの **番号** がそのまま答え。
- H4（答え）: 水位=**レジスタ10**。`FLAG{10}`。

## 2. 盗聴 — 平文を暴く（機密性C）
**説明**: Modbus は暗号化が無い。**Wireshark で自分の通信をキャプチャ** すると、やり取りの中身
（バイト列）がそのまま読める。通信に紛れている **隠し文字列 `FLAG{...}`** を見つけて提出せよ。
**フラグ**: `FLAG{plaintext}`（制御装置の40番台に ASCII で埋め込み。画面には出ない・推測不可）
**ヒント**:
- H1: Wireshark で loopback(lo0)（本番は自分のNIC）をキャプチャ。表示フィルタ `tcp.port == 5020`。
- H2: ポート5020は非標準。右クリック→**Decode As→MODBUS**（生のバイト列を見るだけでも可）。
- H3: `read-hr 0 100` で広い範囲を読む通信を起こし、その応答のバイト列を見る（文字列は**40番台**）。
- H4: 応答のASCIIに `FLAG{...}` が見える（**Edit→Find Packet→String「FLAG」**でも一発）。それを提出。

> 設計意図: 段位1・2は「値当て」ではなく **番号の特定** と **Wiresharkで平文を盗聴** に変更。
> 旧版は「例＝答え」かつ大画面の水位で値が見え、`ascii`一発で解けてしまう欠陥があった（修正済み・2026-11-11）。

## 3. ポンプ奪取 — アクチュエータ操作（完全性I）
**説明**: 制御を無視して、**給水ポンプを君の意志で ON** にしろ。成功すると制御装置がフラグを **100番台の
レジスタ** に出す。read-hr 100 20 で読み、Wiresharkのバイト列（Find「FLAG」）で確認して提出。
**フラグ**: `FLAG{pump_is_mine_coil_write}`
**ヒント**:
- H1: ポンプは **コイル**（ON/OFF）。まず `read-co 0 16` でコイルを読む。
- H2: コイルを **1つずつ書いて**、水位の増え方が変わるものを探せ（給水が始まる＝そのコイルがポンプ）。
- H3: `write-co 5 1`（コイル5をON）。
- H4（ほぼ答え）: ポンプ=**コイル5**。ON にするとフラグが 100番台に出る → read-hr 100 20 → Wiresharkで確認。

## 4. 設定改ざん — 止まらないポンプ（完全性I）
**説明**: ポンプが **絶対に止まらない** 状態を作れ。成功でフラグが **120番台** に出る。
**フラグ**: `FLAG{setpoint_tamper_no_stop}`
**ヒント**:
- H1: ポンプが止まる条件＝「水位が **停止しきい値** 以上」。止まらなくするには、しきい値をどうする？
- H2: 停止しきい値レジスタ（段位1で見つけた**11**）を、水位が **絶対に届かない大きな値** にする。
- H3: `write-hr 11 65535`（0xFFFF）。
- H4（ほぼ答え）: `write-hr 11 65535` → フラグ 120番台 → read-hr 120 20 → Wiresharkで確認。

## 5. 安全無効化 — 最後の砦を外す（完全性I）
**説明**: 水位がHHに達したらポンプを強制停止する **安全インターロック** を **無効化** せよ。
成功でフラグが **140番台** に出る。
**フラグ**: `FLAG{safety_interlock_bypassed}`
**ヒント**:
- H1: 安全機能も **コイル**。初期状態が **ON(True)** になっているコイルが怪しい。
- H2: `read-co 0 16` で True のコイルを探し、**OFF** にする。
- H3: `write-co 6 0`（コイル6をOFF）。
- H4（ほぼ答え）: 安全IL=**コイル6**。OFF にするとフラグ 140番台。

## 6. 実害 — タンクを溢れさせろ（目的達成）
**説明**: ここまでの知識を総動員し、**タンクを実際に溢れさせろ**。水位が 100% に達した瞬間、
溢水アラームが立ち、目的達成のフラグが **160番台** に出る。
**フラグ**: `FLAG{OVERFLOW__you_flooded_the_tank}`
**前提**: 段位4・5をクリア（CTFd の Prerequisites で 4,5 を指定）
**ヒント**:
- H1: **1つの対策だけでは別の安全が止める**。複数の守りを全部くぐれ。
- H2: ①安全（コイル6）をOFF ②停止しきい値（レジスタ11）を到達不能に ③ポンプ（コイル5）をON。
- H3（罠に注意）: 給水/排水レート（レジスタ14=15、15=8）は **触るな**。排水を上げると逆に水位が下がる。
- H4（ほぼ答え）: `write-co 6 0` / `write-hr 11 65535` / `write-co 5 1`。水位(10)が1000でラッチ、
  溢水アラーム=**コイル7** がON。フラグは 160番台 → read-hr 160 30 → Wiresharkで確認。

## B. ボーナス — 保守バックドア（AIで即答しにくい / 時間調整用）
**説明**: 制御装置には運用者用の **隠し保守モード** がある。**全保持レジスタを ASCII 文字列として読む** と、
どこかに手がかりが埋まっている。指示どおりに書き込めば保守フラグが **200番台** に出る。
**フラグ**: `FLAG{hidden_maintenance_backdoor}`
**ヒント**:
- H1: レジスタは16bit=2文字。**数値ではなく文字**が埋まっていることがある。read-hr 0 100 → Wiresharkのバイト列で文字として読む。
- H2: **70番台** に指示が埋まっている。
- H3: 手がかりは「WRITE 4919 TO REG51」。
- H4（ほぼ答え）: `write-hr 51 4919` → フラグ 200番台 → read-hr 200 20 → Wiresharkで確認。
> 実機を実際に読んだ者にしか手がかりが分からない＝AIに丸投げしても解けない。時間が余ったら投入。

## ヒント解放スケジュール（司会用・実働60分の目安）

4人で1つのタンクを攻める公演。**原則は「詰まったら早めに出す」**。下は時刻の**バックストップ**
（この時刻までに進んでいなければ、迷わずそのヒントを開ける）。進みが速ければ前倒しで次へ。

| 経過 | 想定の到達点 | 詰まっていたら開けるヒント |
|------|-------------|---------------------------|
| 0分 | 前半説明おわり・接続開始 | 段位0ヒント（ポート5020） |
| 5分 | 段位1に着手 | 1-H1（read-hrを繰り返し動く値を探す） |
| 10分 | 水位を特定したい | 1-H2（0〜1000で小刻み＝水位／おとりは乱高下） |
| 15分 | 段位1クリア／段位2・3へ | 1-H3→H4、2-H1（Wiresharkフィルタmodbus） |
| 25分 | 段位3（ポンプ）で手が止まる | 3-H2（コイルを1つずつ書いて観察）→必要なら3-H4 |
| 35分 | 段位4・5（改ざん/安全）へ | 4-H2、5-H2（ONのコイルを落とす） |
| 45分 | 段位6（溢水）で詰まる | 6-H2→**6-H3（排水を触るなの罠）**→6-H4 |
| 55分 | 全員で溢水を達成 | 余れば B-H1（ボーナス）／持ち帰り案内 |

> 公演の山場は段位6。**「排水レートを触ると自滅する」罠（6-H3）** は、放置すると全員ハマるので
> 45分前後で必ず触れる。溢水の瞬間はみんなで見る。

## 時間の目安（実働60分・4人協力・ヒント主導）

準備込みでワーキングスタジオは約60分。説明は短く、**適宜ヒントを出しながら**進める前提。

| 区間 | 内容 | 目安 |
|------|------|------|
| 前半 | Modbus超速解説（なぜ侵害できるか・3欠陥） | 10-15分 |
| 本編 | 段位1-6（偵察→…→溢水）。詰まったらヒントを早めに開放 | 30-40分 |
| 調整 | ボーナスB（保守バックドア）。時間が余ったら投入 | 5-10分 |
| 配布 | 持ち帰り課題の案内（repo配布） | 5分 |

4人協力なので「競争」ではなく「全員で1つのタンクを落とす公演」。司会がヒントで速度を調整する。

**AIポリシー（確定）**: 本編の推論パートは **AI禁止**（検証で、AI相当だと偵察→溢水まで約12秒で
終わり学びが飛ぶため。`docs/ai-solvability.md`）。Wireshark/Modbus一般の調べ物に限りAI可。
値の非意味化等の改修はしない前提。

## ヒントを時刻で解放する方法（CTFd）

**CTFd はヒントの「時刻で自動解放」をネイティブには持たない**（ヒントはコスト支払い or 前提ヒントで開く）。
今回の規模なら次のどちらか:

1. **司会が手動解放（推奨・確実）**: 全ヒントを **コスト0** で登録し、普段は **Prerequisites で鎖**にして
   おく（H1を開くとH2が押せる…）。司会が上のスケジュールに沿って「今これ開けてOK」と声かけ。
   4人・1画面の公演なら、司会のPCで該当ヒントのPrerequisiteを外す/口頭で開放でも十分。
2. **APIタイマーで自動解放**: `ctf/ctfd/hint_scheduler.py`（未作成・希望があれば作る）で、CTFd API を
   叩いて指定の分に特定ヒントを開放する。要CTFd起動＋管理トークン。公演を機械任せにしたいとき向け。

## CTFd 側の設定（協力・謎解き公演モード）

- **Visibility > Scoreboard: Hidden**（競争感を消す）。
- **Hints**: すべて **コスト0**。H1→H2→H3→H4 を **Prerequisites で鎖**にして、暴発を防ぎ順に開ける。
- **Prerequisites（問題）**: 1→2→3→4→5→6 のゆるい線形。6 は 4・5 を前提に。
- **アカウント**: 競争しないので **全員で1つの共有アカウント**でよい。

## 値フラグについての注意
段位1・2の値（80.0 / 95.0）は固定値なので口頭で漏れると意味が薄れる。協力公演なので問題ないが、
難しくしたい場合は制御装置側の DEFAULT 値を事前に変えてフラグも対応して更新する（`ctf/target.py` の `DEFAULT`）。
