# 参加者キット — OT-CTF

この演習の対象は、**貯液タンクの水位を自動で制御する制御装置（PLC）**です。
産業用プロトコル Modbus/TCP で通信します。**制御装置の設計図（どの番号が何を表すか）は
渡されません。** 自分で読み書きして、どのレジスタ・コイルが何かを突き止め、最後はタンクを
あふれさせるのが目標です。

- 制御装置の接続先: `<HOST>:5020`（司会が伝えます）
- CTFd（問題とフラグ提出）: `http://<HOST>:8000`

## 1. まず接続する

```bash
python3 mbclient.py --host <HOST> read-hr 0 30     # 保持レジスタ 0〜29 を読む
python3 mbclient.py --host <HOST> read-co 0 16     # コイル 0〜15 を読む
```

主なコマンド:

| コマンド | 意味 |
|----------|------|
| `read-hr <番号> <個数>` | 保持レジスタを読む（16ビットの数値） |
| `read-co <番号> <個数>` | コイルを読む（オン/オフ） |
| `write-co <番号> <0/1>` | コイルを書き換える（ポンプや安全装置はここ） |
| `write-hr <番号> <値>` | 保持レジスタを書き換える（設定値の改ざんはここ） |

値の変化（水位など）は、`read-hr` を**何度も実行して**観察します。
通信の中身（隠し文字列など）は、**Wireshark**でパケットのバイト列を見ます（下記）。

ライブラリとしても使えます:
```python
from mbclient import Modbus
with Modbus("<HOST>", 5020) as c:
    print(c.read_holding(0, 30))
    c.write_coil(5, True)
    c.write_register(11, 65535)
```

## 2. Wireshark で「平文」を見る

Modbus には暗号化がありません。通信を覗けば、値も命令も、埋め込まれた文字列もそのまま読めます。

1. Wireshark を起動し、ネットワークインタフェース（手元だけなら **loopback / lo0**）をキャプチャ。
2. 表示フィルタに **`tcp.port == 5020`**。
3. 今回はポートが標準(502)でないので、パケット右クリック →「**Decode As…**」→ tcp.port 5020 →
   **MODBUS** を選ぶと Modbus として読める（下の**バイト列ペイン**を見るだけでも中身は読めます）。
4. `read-hr` で**広い範囲**（例: `read-hr 0 100`）を読んで通信を起こすと、その**応答パケット**の
   バイト列に、生の値や**隠し文字列**がそのまま現れます。
   - 探すのが大変なら **Edit → Find Packet（⌘F）→ String →「FLAG」** で一発で飛べます。
4. 「どこかに認証（本人確認）はあるか？」を探してみてください（＝ありません）。

## 3. 進め方のコツ（設計図は自分で作る）

- **何度も読んで、変化する値を探す** → それが現在の水位です。その近くに設定値が並んでいます。
- **コイルを1つずつ書き換えて、水位の動きがどう変わるか**を観察 → ポンプや安全装置を特定します。
- 攻撃に成功すると、制御装置が**フラグをレジスタに書き込みます**。`ascii` コマンドで読み出し、
  CTFd に提出してください。

## ルール

- **本編（レジスタの意味を推定してタンクをあふれさせる部分）は AI 禁止**です。自分で読み解くのが
  この演習の目的です。Wireshark の使い方や Modbus 全般の調べ物に AI を使うのは構いません。
- 詰まったら遠慮なく**司会にヒント**を求めてください（ヒントで進み具合を調整します）。

## 注意

- **隔離されたネットワーク専用**です。渡された制御装置以外には絶対に接続しないでください。
  学内・会場のネットワークにはつなぎません。
- これは OT セキュリティを学ぶための、閉じた環境での演習です。
